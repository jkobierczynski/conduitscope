Manual / Setup: Linux & Windows

Setup: build conduitscope from source

There is no distributed binary -- you build it. One C++17 toolchain, CMake >= 3.16, and (optionally) libpcap/Npcap for live capture. Everything else (CLI11) is vendored.

Pick your platform below; the same CMake project drives both.

bashLinux -- Release build, with live-capture support

# optional, only needed for -i/--interface live capture:
$sudo apt install libpcap-dev

$cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
$cmake --build build -j

# optional: let an ordinary user open live captures without sudo (see callout below)
$sudo apt install -y libcap2-bin
$sudo setcap cap_net_raw,cap_net_admin=eip build/conduitscope

# optional: run the fixture-based regression suite
$ctest --test-dir build --output-on-failure

$build/conduitscope version
conduitscope 0.3.2  [GNU 13.3.0, Linux, Release build, live capture: libpcap/Npcap]
PowerShellWindows -- MSVC via Visual Studio 2022

# optional, only needed for -i/--interface live capture:
# download and install the Npcap SDK from https://npcap.com/#download, then either
# set NPCAP_SDK_DIR or pass -DNPCAP_SDK_DIR=<path> to cmake below

PS>cmake -S . -B build -G "Visual Studio 17 2022" -A x64
PS>cmake --build build --config Release

PS>build\Release\conduitscope.exe version
conduitscope 0.3.2  [MSVC 19.4x, Windows, Release build, live capture: libpcap/Npcap]
bash (MSYS2)Windows -- MinGW-w64, from an MSYS2/MinGW shell

$cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
$cmake --build build -j

$build/conduitscope.exe version
Live capture: build-time SDK vs. runtime driver

On Linux, building against libpcap-dev is enough -- the runtime library is the same package. On Windows the two are separate: the Npcap SDK is headers and an import library, needed only at build time; actually running -i on a given Windows machine also needs the Npcap runtime/driver installed on that machine, separately, even if the binary itself was built elsewhere. See USER_GUIDE.md's LIVE CAPTURE section for the full build-time-vs-runtime distinction.

CAP_NET_RAW on Linux

Opening a live capture (-i, even against loopback) needs CAP_NET_RAW, which an ordinary Linux user doesn't have by default. The setcap step above grants that capability to the built binary itself, once, as a one-time root step -- every run after that, by any user, works without sudo. Without it, -i (and the live_capture_* CTest cases that exercise it) need root. This is the same fix .github/workflows/ci.yml applies before its own CI test suite runs.

A dependency-free build

To guarantee a build with no libpcap/Npcap dependency at all -- e.g. for a decode-only deployment that will only ever read offline files -- skip the detection step entirely:

Force a build with no live-capture support

$cmake -S . -B build_nolive -DCMAKE_BUILD_TYPE=Release -DCONDUITSCOPE_ENABLE_LIVE_CAPTURE=OFF
$cmake --build build_nolive -j
$build_nolive/conduitscope version
conduitscope 0.3.2  [GNU 13.3.0, Linux, Release build, live capture: not built]

$build_nolive/conduitscope decode -i eth0
error: this build was compiled without live capture support (-DCONDUITSCOPE_ENABLE_LIVE_CAPTURE=OFF or libpcap/Npcap not found)

Note Windows's own path separator above (\ vs. /) -- conduitscope itself doesn't care which separator you use for -r/-o/etc. (the C++ standard library and Windows's own APIs both accept forward slashes), but PowerShell's and cmd.exe's own path-completion and copy-pasted documentation elsewhere will usually show backslashes, so both are shown throughout this manual to match whichever shell a given example is for.

Capturing your own traffic

To decode traffic you've actually captured -- from a Modbus simulator such as pymodbus, or a public sample set like the 4SICS ICS pcaps -- capture it with any standard tool and decode the resulting file:

Capture with tcpdump, decode with conduitscope

$tcpdump -i <iface> -w capture.pcap port 502 or port 20000 or port 2404 or port 102 or port 44818 or port 2222 or port 47808 or port 5094 or port 4840
$build/conduitscope decode -r capture.pcap

Or skip the intermediate file and capture straight into conduitscope -- see Live capture & continuous capture.
