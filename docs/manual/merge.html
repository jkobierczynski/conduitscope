Manual / merge -- combine multi-site reports

merge -- combine multi-site reports

Combines N independent inventory --format json reports (one per tap point) into one site-wide asset/communications/zone/conduit matrix. Currently the only report kind merge supports -- merging policy/detect/baseline reports across tap points is a reasonable follow-up, not built yet.

Why a separate step

inventory itself only ever sees one capture (one tap point) at a time. A real site usually has several SPAN/TAP collectors, each running its own capture process (see Live capture & continuous capture's "one tap point per process" note) and its own analysis pass. merge inventory is the step that reassembles those separate views back into one picture -- assets seen at more than one tap point are unioned, not duplicated, and zones/conduits are always freshly re-derived from the merged result rather than merged themselves (so the merged zone model reflects the combined traffic, not a union of each site's own possibly-inconsistent zone boundaries).

Produce one JSON report per tap point

Two independent inventory reports

$conduitscope inventory -r tap1.pcap -T json -o site_a.json
$conduitscope inventory -r tap2.pcap -T json -o site_b.json

Merge them

One combined, site-wide report

$conduitscope merge inventory site_a.json site_b.json
OT asset inventory
  capture: merged: 2 report(s) (site_a.json, site_b.json)

9 asset(s) observed, 17 total packet(s) in capture, 0 skipped

ASSETS (9):
  10.0.5.21  00:0c:29:de:ad:01  [client]  dnp3, s7comm  (6 packet(s))
      role: HMI/Engineering Station  (heuristic, low confidence)
  192.168.1.10  00:0c:29:aa:bb:cc  [server]  modbus  (5 packet(s))
      first seen: 2023-11-14 22:13:20.000000Z  last seen: 2023-11-15 03:46:41.001000Z
      role: PLC/RTU  (heuristic, low confidence)
  ...

Notice 192.168.1.10's packet count (5) and first-seen time are the union of what each separate report observed -- one asset merged from two partial views, not two rows.

Every output format inventory itself supports also works on the merged result -- -T json, -T csv, -T stix, --diagram, --policy-out -- so a site-wide Mermaid diagram or inferred policy comes from the same merge inventory ... --diagram site.mmd --policy-out site_policy.yaml invocation.

A site-wide diagram and inferred policy from the merged view

$conduitscope merge inventory site_a.json site_b.json --diagram site.mmd --policy-out site_policy.yaml

Scaling to more than two tap points

merge inventory takes any number of report files on the command line -- list every tap point's JSON report:

Four tap points at once

$conduitscope merge inventory site_a.json site_b.json site_c.json site_d.json -o site_wide.json -T json

A typical unattended pipeline: each site runs its own capture continuously (Live capture & continuous capture), a scheduled job runs inventory -r <latest rotated files> -T json -o <site>.json per tap point, and a central job periodically runs merge inventory across all of them.
