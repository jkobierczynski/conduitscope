Manual / policy validate -- zone/conduit compliance

policy validate -- zone/conduit compliance

Checks a capture against a hand-authored YAML zone/conduit policy: every observed flow is either ALLOWED (matches a declared conduit), a VIOLATION (crosses zones with no permitting conduit), or UNCLASSIFIED (an endpoint isn't in any declared zone at all). This is the IEC 62443 FR5 (Restricted Data Flow) angle -- the opposite direction from inventory, which infers a policy from traffic instead of checking against one.

A minimal policy file

Two zones (named sets of networks), and conduits (named permitted flows between zones, by protocol and port):

yamltests/policies/compliant.yaml

zones:
  hmi_zone:
    description: "HMI / engineering workstation"
    networks:
      - 192.168.1.50/32
  plc_zone:
    description: "PLC"
    networks: [192.168.1.10/32]

conduits:
  - name: "HMI polls PLC via Modbus"
    from: hmi_zone
    to: plc_zone
    protocols: [modbus]
    ports: [502]

See USER_GUIDE.md's POLICY FILE FORMAT for the complete schema: VLAN-membership zones (by MAC/EtherType, for PROFINET/GOOSE/SV/EtherCAT which have no IP layer at all), bidirectional conduits, function-level restrictions, and every validation rule a malformed policy file is checked against before any packet is read.

A real violation

Same capture, a policy that only permits Modbus on the wrong port -- the flow is between two known zones, but no conduit permits it on port 502, so it's a VIOLATION (not UNCLASSIFIED -- that's reserved for an endpoint outside every declared zone):

--policy tests/policies/wrong_port.yaml

$conduitscope policy validate -r tests/sample_modbus.pcap --policy tests/policies/wrong_port.yaml
Zone/conduit policy validation
  policy:  tests/policies/wrong_port.yaml (2 zone(s), 1 conduit(s))

Result: NON-COMPLIANT (1 violation(s), 0 unclassified flow(s))

VIOLATIONS (1):
  [1] 192.168.1.50 -> 192.168.1.10:502 (modbus)  (modbus, 3 packet(s))
      zones: hmi_zone -> plc_zone
      a conduit exists between zone 'hmi_zone' and zone 'plc_zone', but none permits modbus traffic on port 502

Conduits never exercised by this capture (1):
  - HMI to PLC on the wrong port
Exit code encodes the verdict

0 = COMPLIANT, 3 = NON-COMPLIANT (a real violation and/or unclassified flow was found), 1 = couldn't even run (bad policy file, unreadable capture). A script can distinguish "ran fine, found a problem" from "didn't run" without parsing output -- see EXIT STATUS.

Unclassified traffic

An endpoint that isn't in any declared zone -- different from a violation, which requires both endpoints to be known:

Traffic from hosts this policy never declared a zone for

Output formats

-T/--format: text (default), json, or curated one-line-per-finding SIEM formats cef/leef/syslog -- see JSON output & filtering and detect's SIEM export section for the shared CEF/LEEF/syslog conventions across every subcommand that supports them.

A violation as a CEF one-liner, ready for a SIEM forwarder

$conduitscope policy validate -r tests/sample_modbus.pcap --policy tests/policies/wrong_port.yaml --format cef
CEF:0|conduitscope|conduitscope-policy|0.3.2|policy-violation|Zone/Conduit Policy Violation|8|src=192.168.1.50 dst=192.168.1.10 dpt=502 proto=modbus cat=policy-violation msg=a conduit exists between zone 'hmi_zone' and zone 'plc_zone', but none permits modbus traffic on port 502 cs1Label=Client Zone cs1=hmi_zone cs2Label=Server Zone cs2=plc_zone cnt=3

Discover, then enforce

Don't have a policy file yet? inventory infers a first-draft one from observed traffic, which feeds straight back into policy validate:

Round-trip: infer a policy, then validate against it

$conduitscope inventory -r tests/sample_inventory.pcap --policy-out inferred.yaml
$conduitscope policy validate -r tests/sample_inventory.pcap --policy inferred.yaml
Result: COMPLIANT

Review an inferred policy before using it to gate anything real -- it's a first draft of what was observed, not a statement of what's intended. See inventory's own policy-out section.
