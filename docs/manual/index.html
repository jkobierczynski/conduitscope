Manual / conduitscope manual

conduitscope -- extended manual

A worked-example companion to the reference docs: every command on every page below was actually run against the real fixture captures shipped in tests/, and the output shown is the real, unedited (occasionally truncated for length) result of that run on conduitscope 0.3.4.

conduitscope is a passive OT/ICS network-security monitoring CLI: it reads pcap/pcapng captures (or a live interface) and decodes, inventories, audits, and detects findings across Modbus/TCP, DNP3, S7comm, IEC 60870-5-104, EtherNet/IP, PROFINET, IEC 61850 (GOOSE/SV/MMS), EtherCAT, BACnet/IP, HART-IP, OPC UA, MELSEC, FINS, MQTT, and more. It never transmits anything onto the wire -- see PASSIVE-MODE GUARANTEE in the User Guide.

How this manual is organized

Eleven subcommands, eleven pages, roughly matching how you'd actually use the tool: read a capture file first (decode, info), then move to live/continuous capture, then to the security- and compliance-facing commands (policy validate, inventory, detect, baseline, evidence), then multi-site merge and a dedicated page on JSON output and filtering with real jq (Linux/macOS) and PowerShell (Windows) recipes, escape characters included.

Every feature, at a glance

Setup
Build from source on Linux and Windows, with and without live-capture support.
decode
Per-packet decode: text/json/csv/fields/zeek, BPF filters, display filters, hex dump, -V details.
info
File metadata, protocol histogram, IPv4/Ethernet/TCP conversations and endpoints, Follow Stream.
Live & continuous capture
conduitscope interfaces, decode -i, and capture's disk-bounded rotated-file recorder.
policy validate
Zone/conduit compliance checking against a YAML policy file -- the IEC 62443 FR5 angle.
inventory
Passive asset discovery: assets, communications, inferred zones, Mermaid/DOT diagrams, STIX 2.1.
detect
MITRE ATT&CK for ICS findings with evidence/novelty/severity axes, CEF/LEEF/syslog export.
baseline
Learn normal protocol-operation behavior, then flag new conduits/operations/address ranges.
evidence
One audit-binder-ready report: topology + policy + detect + baseline + integrity hashes.
merge
Combine inventory reports from several independent tap points into one site-wide view.
JSON & filtering
Piping --format json through jq (Linux/macOS) and PowerShell (Windows), escaping compared.

60-second tour

Every example below reads tests/sample_modbus.pcap, one of the small synthetic fixtures this project's own test suite uses (see tools/make_sample_pcap.py) -- real enough to show the tool's actual output, small enough to read in full.

Decode a capture as text, then as JSON

$conduitscope decode -r tests/sample_modbus.pcap
#1  0.000000  192.168.1.50:51000 -> 192.168.1.10:502 (modbus)  [modbus]  Read Holding Registers: request: read 10 holding register(s) starting at address 0
#2  1.001000  192.168.1.10:502 (modbus) -> 192.168.1.50:51000  [modbus]  Read Holding Registers: response: 20 data byte(s) = 00 00 00 01 00 02 00 03 00 04 00 05 00 06 00 07 00 08 00 09
#3  2.002000  192.168.1.10:502 (modbus) -> 192.168.1.50:51000  [modbus]  Read Holding Registers: exception response to Read Holding Registers: Illegal Data Address

$conduitscope decode -r tests/sample_modbus.pcap -T json | jq '.[0].summary'
"Read Holding Registers: request: read 10 holding register(s) starting at address 0"

Every page that follows does the same thing for a different subcommand or feature: a short explanation, then real commands against real fixtures, with the real output underneath.

About the example captures

Two kinds of capture appear throughout this manual:

  • Synthetic fixtures (tests/sample_*.pcap) -- small, deterministic captures this project generates itself (tools/make_sample_pcap.py) specifically to exercise one feature cleanly. Most examples use these, because their output is short and stable.
  • Real-world captures (tests/real_captures/<protocol>/*.pcap) -- genuine third-party OT/ICS traffic pulled from public research repositories (see each directory's own ATTRIBUTION.md for exact provenance and licensing). A handful of pages below run the same commands against one of these too, to show the tool against traffic it didn't generate itself.
